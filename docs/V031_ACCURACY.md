# V0.3.1 accuracy design and compatibility

Source audit confirmed V0.3's `closest('section,article,nav,header,footer,main,[role="region"]')`, first-N renderer and collection-order byte truncation. A heading with only main above it could expand to the page. Early generic nodes displaced later controls/images. Repeated per-node CSS hid useful relationships; Concise also omitted properties. The attachment's existing features and security code were retained.

## Boundary selection

`boundary.js` evaluates at most 11 ancestors within a 20 ms best-effort sub-budget. It stops before main/body/html/page-main roles. Candidates use actual bounding rectangles, visible direct-child relationships (up to 64), semantic tags/roles, flex/grid, internal spacing, border/shadow/painted rounded boundaries and expansion penalties. It rejects disproportionate tall candidates and direct groups containing multiple unrelated landmarks. Transparent one-child wrappers are penalized. A score of at least 12 chooses the strongest local candidate; ties retain the nearer one. Otherwise the nearest non-rejected structural parent or selected element is retained. If the selection itself is a page-level wrapper, section mode returns a clear 422 `prompt-section-too-broad`, directing the user to a local child or page scope.

The returned boundary string remains compatible. Optional `boundaryDecision` records method, tag, distance, score, fixed reason labels and bounded candidate/rejection summaries. No IDs/classes/URLs are used as instructions or heuristic keywords. A nearest card can beat a distant semantic section, and navigation retains its local boundary. Tall heroes, unusual markup and ambiguous grouping can still yield smaller or imperfect boundaries; review the decision. These rules do not claim universal segmentation.

## Collection and prioritization

The same collector uses bounded breadth-first discovery with a pinned selected ancestry, rather than stopping at the first 55 encountered nodes. It keeps small descriptors for no more than 1,500 queued/visited elements and selects at most 55 output candidates with their captured ancestors. Discovery stops around 95 ms; CSS materialization shares the 120 ms total best-effort budget and processes priority/ancestor chains first, so a time cutoff does not drop late CTAs in favor of early generic nodes. DOM calls can exceed a time check; the existing five-second backend deadline and browser memory/time limits remain the outer controls. Depth is still 16. `display:contents` can preserve a zero-box parent as structural context. Visibility is still heuristic: clipping, stacking and positioned children outside an excluded ancestor are not fully solved.

Heading/control/media/landmark/layout importance, selected status and visible text drive priority. Original discovery IDs and actual parent references remain; DOM sibling indices are stored before priority traversal. The renderer sorts siblings by those indices, keeping light/shadow child lists distinct. Open-shadow children explicitly mark the parent reference as a host, rather than pretending the host is their direct DOM parent. It does not invent React components or reparent isolated important nodes. A whole ancestor chain must fit before admitting a candidate. Both the 48,000-byte sanitized evidence budget and the 4/12/28 detail budgets apply priority with ancestor closure. The selected chain may exceed the nominal detail count (never the byte budget), and that exception is disclosed. Missing selected nodes, invalid paths and omitted coverage are reported explicitly.

The current snapshot is still the visible viewport, not an automatic scroll crawl. Unvisited/omitted nodes are unknown. Absolute/fixed content in excluded ancestors, complex shadow/iframe/canvas cases and occlusion remain limitations. No click interactions are added.

## Exact styles and geometry

Included nodes keep every available sanitized property, even in Concise mode. `style_groups.py` factors equal `(property, value)` pairs by their exact node membership and category: layout, typography, appearance or motion. Each node references shared groups plus unique values. Merging those maps exactly reconstructs its included sanitized styles; tests verify equality, mixed overlapping membership, arbitrary properties and meaningful differences. Equal computed values do not establish inheritance, authored CSS rules or component reuse. The factoring never changes a measured string to an approximation.

The collector adds useful flex, gap, overflow, sizing, object-position and font-style measurements. It preserves URL-free computed gradients; asset URLs are omitted. Value-length limits remain 180 characters, with explicit property flags. Privacy redactions/removals are also flagged. Internal CSS whitespace is preserved so quoted font names and similar values do not change meaning. Existing raw element inspection/JSON is unchanged; prompts do not claim sanitized/trimmed strings are original stylesheet source.

Rectangles retain viewport CSS-pixel coordinates. Parent-origin deltas are derived from captured rectangles and labelled as including transforms/borders, not invented margins/padding. Viewport intersections describe geometry only, not complete ancestor clipping or pixel visibility. DOM accessibility attributes are evidence, not a complete accessible name computation or an accessibility audit.

## Prompt and API compatibility

The eight numbered top-level sections and prompt response schema 0.3 remain. Subsections organize content/assets, style categories, observed/recommended interaction, responsiveness and accessibility. Existing targets/detail/style/mode enums, endpoint, request header, frame/reference checks, edit/copy/regenerate and optional AI interpretation are preserved. Inspection JSON stays 0.1; internal evidence stays `0.3-evidence` with optional additive fields. Older evidence without them still renders. The frontend only changes version/help text.

Recommendations are labelled; no extra breakpoints, hover endpoints, assets or hidden states become facts. Existing recorded hover comparisons remain available for the exact selected element. AI interpretation is appended separately and remains untrusted. The provider adapter is unchanged and only mock-tested here.

Network policy, proxy pinning, Chromium sandbox, Compose services/capabilities, seccomp, devcontainer, session limits, body/origin checks and credentials handling are unchanged. Collection still excludes form values, editable copy, HTML, cookies, storage and signed URLs; composed private ancestors are handled conservatively. No new package dependency was added or upgraded. Package version metadata and the Node test command changed only.
